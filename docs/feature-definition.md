# 機能定義書

## 1. 文書情報

- 対象アプリ: 麻雀スコアシートモバイル
- 対象バージョン: `package.json` の `1.1.3`
- 対象プラットフォーム: Expo / React Native による iOS、Android、Web
- 参照元: `README.md`、`app/`、`screens/`、`components/`、`database.ts`、`utils.ts`、`liveSession.ts`、`firebase.ts`、`firestore.rules`、`__tests__/`

## 2. アプリ概要

麻雀スコアシートモバイルは、3人麻雀または4人麻雀の半荘ごとのポイント、チップ移動、順位、総合結果をローカル端末上で記録・閲覧・共有するモバイルアプリである。

主な利用シーンは次のとおり。

- プレイヤー名と人数を指定して新規ゲームを開始する。
- 半荘ごとのスコアを入力し、順位を自動判定して保存する。
- 半荘に紐づくチップ移動を別途記録する。
- 現在の総合スコア、順位分布、記録履歴を確認する。
- ゲームを中断、再開、終了する。
- 終了済みゲームを過去履歴として閲覧、削除する。終了済みゲームは6桁の数字のセッションコードで共有する。
- 共有されたセッションコードまたはセッションリンクからゲームを閲覧し、履歴に保存する。
- 進行中の対局をリアルタイム共有し、同じ卓のメンバーが各自の端末で閲覧する。

## 3. 画面構成と遷移

### 3.1 ルート処理

`app/_layout.tsx` はアプリ起動時に SQLite データベースを初期化し、ディープリンクを監視する。

`mahjong-score://live?code=<セッションコード>` 形式のリンクを受け取った場合は、共有セッションの閲覧画面へ遷移する（4.13節、4.17節）。ローカルデータを変更しないため、進行中ゲームがあっても確認ダイアログは表示しない。それ以外のリンク（廃止した静的共有の `mahjong-score://import?code=…` を含む）は無視する。

### 3.2 メイン画面状態

`app/index.tsx` は次の画面状態を管理する。

| 状態 | 表示画面 | 用途 |
| --- | --- | --- |
| `setup` | `SetupScreen` | 初期設定、再開、履歴、ゲームの取り込み（セッション参加） |
| `game` | `GameScreen` | 進行中ゲームの入力・集計 |
| `pastGames` | `PastGamesScreen` | 終了済みゲーム一覧 |
| `viewPastGame` | `GameScreen` | 過去ゲームまたは保存した共有ゲームの読み取り専用閲覧 |
| `liveView` | `GameScreen`（`liveSessionCode` 指定） | 共有セッション（進行中・終了済み）の読み取り専用閲覧 |

起動時に未終了ゲームがある場合は、自動的に `game` 状態で再開する。URLパラメータ `liveCode` が渡された場合は、そのセッションをライブ閲覧する。

### 3.3 基本遷移

- `SetupScreen` から新規ゲーム開始または中断ゲーム再開で `GameScreen` に遷移する。
- `GameScreen` で中断すると `SetupScreen` に戻る。
- `GameScreen` でゲーム終了すると `SetupScreen` に戻る。
- `SetupScreen` から過去ゲーム一覧へ進み、一覧からゲームを選択すると読み取り専用の `GameScreen` に遷移する。
- 取り込み欄にセッションコードを入力するかセッションリンクを開くと、ライブ閲覧画面に遷移する。ライブ閲覧から戻るとセットアップ画面に戻り、履歴に保存した場合は保存したゲームの閲覧画面へ進める。
- 一度参加したセッションは過去ゲーム一覧に表示され、選ぶとコード入力なしでライブ閲覧画面に再入室できる（4.17節、Issue #58）。

## 4. 機能定義

### 4.1 ゲーム設定

ユーザーはセットアップ画面の「新規ゲーム」で麻雀タイプとプレイヤー名を設定できる。

- 麻雀タイプは3人麻雀または4人麻雀から選択する。
- プレイヤー名は選択した人数分だけ入力する。
- プレイヤー名は必須で、最大6文字までとする（Issue #60 で4文字から変更）。
- プレイヤー名入力欄には、この端末で直近に作成したゲームのプレイヤー名を初期値として入れる（編集可能。共有から取り込んだゲームは対象外）。
- 入力エラーがある場合、ゲームは開始せずアラートを表示する。
- 中断中ゲームが存在する状態で新規ゲームを開始する場合、確認後に中断中ゲームを整理する。
- 半荘記録もチップ記録もない中断ゲームは削除する。
- 記録がある中断ゲームは終了済みとして保存する。

### 4.2 中断中ゲームの再開

未終了のゲームはセットアップ画面に一覧表示される。

- 表示内容は開始日、麻雀タイプ、プレイヤー名、半荘数とする。
- 一覧項目をタップすると該当ゲームを再開する。
- アプリ起動時に未終了ゲームがある場合は、最新の未終了ゲームを自動的に開く。

### 4.3 ポイント入力とスコア記録

進行中ゲームでは、プレイヤーごとにドラムロール入力 UI で半荘ポイントを入力する。

- 入力単位は `+10`、`+1`、`-10`、`-1` とする。
- 入力範囲は `-200` から `+200` までとする。
- 初期値は全員 `0` とする。
- 正の値は緑、負の値は赤、ゼロは通常色で表示する。
- 入力中の合計値を表示し、合計がゼロでない場合はエラー色で示す。
- リセット操作で全プレイヤーの入力値を `0` に戻せる。

スコア記録時の制約は次のとおり。

- 全員 `0` の場合は記録できない。
- 合計が `0` でない場合は記録できない。
- 記録時にポイント降順で順位を自動判定する。
- 同点の場合は同順位とし、次順位は競技順位方式で採番する。例: 1位タイが2人いる場合、次は3位。
- 記録成功時は現在の半荘番号で保存し、次の半荘番号へ進め、入力値をリセットする。

### 4.3.1 プレイヤー名の変更（Issue #58）

進行中ゲームでは、対局の途中でもプレイヤー名を変更できる。

- 画面最上部の小さい「名前変更」ボタン（Issue #60 で入力エリアの下から移動）からモーダルを開き、各プレイヤーの名前を編集する。
- 名前は必須・最大6文字とし、同じ名前の重複は不可とする（記録はプレイヤー名で紐づくため）。前後の空白は除去する。
- 変更すると `game_players` に加えて、記録済みの `scores`・`chips` のプレイヤー名も書き換える。名前の入れ替えにも対応する。
- リアルタイム共有中は変更後の状態を参加者へ送信する。

### 4.4 チップ移動記録

進行中ゲームでは、スコアとは別にチップ移動を記録できる。

- 入力 UI、入力範囲、色分け、リセット操作はポイント入力と同等とする。
- 入力エリアの背景はクリーム色（`#ffecb3`、Issue #60 で濃くした）としてポイント入力と区別する。
- 全員 `0` の場合は記録できない。
- 合計が `0` でない場合は記録できない。
- 記録先の半荘番号は現在のスコア入力対象の一つ前、すなわち直近で記録済みの半荘とする。
- 記録成功時はチップ入力値をリセットする。

### 4.5 総合スコア表示

`SummaryCards` はゲーム中および読み取り専用閲覧時に総合結果を表示する。

- プレイヤーごとに、スコア合計とチップ合計を足した総合スコアを表示する。
- 総合スコアは正の値を緑、負の値を赤、ゼロを通常色で表示する。
- 順位ごとの回数をバッジで表示する。
- チップ合計がゼロでない場合はチップ合計を補足表示する。

### 4.6 記録履歴表示

`HistoryTable` はスコア履歴とチップ履歴を統合して新しい順に表示する。

- スコア履歴は半荘ごとにグループ化して表示する。
- チップ履歴は同一タイムスタンプごとにグループ化して表示する。
- スコア行には半荘番号、記録日時、プレイヤー別ポイント、順位バッジを表示する。
- チップ行にはチップ記録日時とプレイヤー別チップ値を表示する。
- 編集可能状態では、長押し操作で削除確認を表示する。
- 読み取り専用状態では、長押し削除を無効にする。

### 4.7 記録削除

進行中ゲームでは履歴から記録を削除できる。

- 半荘スコア行を長押しすると、その半荘のスコア記録と同じ半荘番号のチップ記録を削除する。
- 半荘削除後、残った半荘は記録時刻順に `1` から採番し直す。
- チップ行を長押しすると、そのチップ移動グループのみを削除する。
- 削除前には確認ダイアログを表示する。

### 4.8 ゲーム中断

進行中ゲームでは中断操作ができる。

- 中断ボタン押下時に確認ダイアログを表示する。
- 中断したゲームは `finished = 0` のまま保持する。
- 中断後はセットアップ画面に戻り、中断中ゲーム一覧から再開できる。

### 4.9 ゲーム終了

進行中ゲームでは終了操作ができる。

- ゲーム終了ボタン押下時に最終結果モーダルを表示する。
- モーダルには総合スコア順のランキング、上位メダル、順位回数を表示する。
- 確定時、記録が一件もないゲームは削除する。
- 確定時、記録があるゲームは `finished = 1` に更新して終了済みとして保存する。
- 保存後、保存上限（4.10節）を超えた古いゲームを自動削除する。
- 終了後はセットアップ画面に戻る。

### 4.10 過去ゲーム一覧

終了済みゲームは過去ゲーム一覧で閲覧できる。

- 一覧には開始日、麻雀タイプ、半荘数を表示する。終了済みゲームはプレイヤーごとの最終スコア（スコア合計＋チップ合計。正は緑・負は赤、正の値は `+` 付き）を表示し、未終了のゲームはプレイヤー名のみを表示する（Issue #78）。
- 共有セッションから履歴に保存したゲームには `共有` バッジを表示する。
- タップすると読み取り専用の詳細画面を開く。
- 各ゲームの ☆ をタップするとお気に入りに登録・解除できる（Issue #60）。登録済みは ★ で表示する。
- 「過去のゲーム」の見出しの下には「保存は最大100件まで（お気に入りは最大20件）」の1行だけを表示する。選択モード中は「削除するゲームをタップして選んでください」とする（Issue #88）。
- 終了済みゲームも参加したセッション（4.17節）も存在しない場合は空状態メッセージ「保存されたゲームはありません」を表示する。
- 「保存データをクリア」ボタンは Issue #81 で削除した（4.15節）。

#### 選択削除（Issue #74）

- ヘッダー右上の「選択」ボタンで選択モードに入り、チェックしたゲームをまとめて削除できる。「選択」ボタンは選択できるゲームが1件以上ある場合のみ表示し、選択モード中は「キャンセル」ボタンに変わる。ゲームカードの長押しでは選択モードに入らない（Issue #88）。
- 選択モードではゲームカードをタップするたびに選択・解除を切り替える。画面下部の操作バーに「すべて選択」（全件選択済みのときは「選択解除」）ボタンと「削除（n件）」ボタンを表示する。1件も選択していない間は削除ボタンを押せない。
- 削除ボタンを押すと「選択した n 件のゲームを削除しますか？この操作は取り消せません。」の確認ダイアログを表示し、承認すると選択したゲームを1つのトランザクションでまとめて削除して選択モードを終える。
- お気に入りのゲーム（Issue #78）と、ホストとしてリアルタイム共有中（進行中）のゲームは選択できない（半透明で表示する）。参加したセッション（閲覧モードへの再入室用、4.17節）は選択モード中は一覧に表示しない。
- 一覧の更新で無くなったゲームは選択から外し、選択できるゲームが無くなった場合は選択モードを終える。
- 選択モードでは、お気に入りのゲームのカードの縦中央にカード幅いっぱいの紺色（`#1e3c72`）の帯を重ね、白文字で「お気に入りのため削除不可」と表示する（Issue #88 で追加、Issue #90 で右上の斜めのワッペンから変更）。帯はカードの半透明表示の影響を受けないようカードの外側に重ねる。通常モードでは表示しない。
- 選択モードの出入りや選択・解除でカードの大きさと中身の位置が変わらないようにする（Issue #90）。基本のカードに常に太さ2の透明な枠線（`borderWidth: 2`）を確保し、選択時は枠線の色だけを変える。チェックボックスは選択モードのときだけ絶対配置で重ねるため、レイアウトには影響しない。
  - Issue #90 ではカード左側に常にチェックボックス用の余白（`paddingLeft: 44`）を確保してその上に配置していたが、Issue #96 でこの余白をなくし、チェックボックスをカード左上の角にまたがる位置（中心が角に重なる位置）に重ねる形に変更した。
- 選択モードでも ★ / ☆ と同じ大きさの領域を確保し（☆ の位置は空欄、★ はタップ不可の表示のみ）、「4人麻雀」などの表示位置が通常モードとずれないようにする（Issue #94）。

#### 保存上限とお気に入り（Issue #60）

Issue #60 本文の「50件」は、Issue コメントの確定値（お気に入りを含めて合計100件・お気に入りは最大20件）に読み替えている。

- 終了済みゲームはお気に入りを含めて合計最大100件まで保存する。ゲーム終了・共有セッションからの保存（取り込み）のたびに、100件を超えた分を通常データ（お気に入り以外）の作成日時の古いものから自動で削除する。保存したばかりのゲームは削除しない。
- お気に入りは最大20件とし、合計件数（100件）には数えるが、自動削除の対象外とする。
- お気に入りが20件に達した状態で新たに登録しようとした場合は、自動解除はせず、「お気に入りは最大20件です」とアラートで知らせて登録しない。
- お気に入りの登録・解除だけではゲームを削除しない。
- お気に入りは最大20件しか存在しないため、保存枠がお気に入りだけで埋まって新規ゲームが保存できなくなることは構造上起こらない。また削除処理に失敗しても保存自体は成功させる。

### 4.11 ゲーム共有（終了済みゲームのコード共有）

読み取り専用のゲーム詳細画面（過去ゲーム）では、終了済みゲームを6桁の数字のセッションコードで共有できる（Issue #46）。仕組みはリアルタイム共有（4.17節）と共通で、最初から終了状態（`ended: true`）のセッションとして Firestore の `sessions/{code}` に登録する。

- ヘッダーの「共有」ボタンを押すと確認ダイアログを表示し、「コードで共有」を選ぶとセッションを発行する。発行中はボタンを「発行中…」表示にして重複発行を防ぐ。
- 発行後はコード表示モーダルを開く。モーダルはリアルタイム共有と同じ構成で、コード・有効期限を表示し、OS標準共有シートでの送信（コードとセッションリンク `mahjong-score://live?code=<code>`）、コードのコピーができる。説明文は「「ゲームを取り込む」にこのコードを入力すると閲覧・保存できます」とする（Issue #60 で簡潔にした）。
- モーダルを閉じた後も、画面上部にコードと有効期限を表示し続ける（Issue #60）。タップでモーダルを再表示する。
- 有効期限は発行時刻から48時間（進行中セッションと同じ）とする。
- 共有するたびに新しいコードを発行する。発行したコードはローカルに保存しない。
- 発行に失敗した場合（通信不可など）はエラーアラートを表示する。
- 受け取った側は「ゲームを取り込む」にコードを入力するかリンクを開くと、有効期限内であれば終了状態で閲覧でき、「対局を履歴に保存」で履歴に保存できる（4.17節 参加者側）。有効期限（発行から48時間）を過ぎたコードは、終了済みのセッションでも期限切れとして扱い、閲覧・保存できない（Issue #108）。
- 有効期限が切れた後に再び共有したい場合は、もう一度「共有」から新しいコードを発行する。

### 4.12 ゲーム取り込み

セットアップ画面の「ゲームを取り込む」ボタンを押すと取り込みモーダルを開き、セッションコードまたはセッションリンクを入力して共有セッションに参加する。

- セットアップ画面では、「新規ゲーム」カードの下に「ゲームを取り込む」「過去のゲームを見る」の順にボタンを並べ、その下に「過去のゲーム n件（お気に入り n件）」と保存件数を小さく表示する（Issue #81 で「過去のゲーム履歴管理」カードを廃止）。件数は終了済み・中断中を合わせたゲーム数とする。
- 「過去のゲームを見る」ボタンは、終了済みゲームまたは再入室できる参加セッション（4.17節）がある場合のみ表示する。

- 入力が空の場合は入力エラーを表示する。
- 入力が6桁の数字のセッションコード（空白とハイフン除去後）またはセッションリンクの場合は、セッションに参加する（4.17節）。進行中のセッションはリアルタイムで閲覧でき、終了済みのセッションは閲覧して履歴に保存できる。
- 有効期限（発行から48時間）を過ぎたセッションのコードを入力した場合は、内容を表示せず「有効期限切れ」のエラー（「セッション「123456」の有効期限が切れました。閲覧・保存はできません」）を表示し、「OK」でセットアップ画面に戻る。履歴への保存もできない（Issue #108）。ただし、そのコードの対局をすでに取り込み済みの場合は、従来どおり保存済みの対局を開く（4.17節）。
- それ以外の入力（廃止した静的共有コード・静的共有リンクを含む）はエラーアラートを表示する。

### 4.13 ディープリンク

アプリは `mahjong-score://live?code=<セッションコード>` のディープリンクを処理する。

- コールドスタート時の初期URLを処理する。
- バックグラウンド復帰時のURLイベントを処理する。
- セッションリンクを受け取ると共有セッションの閲覧画面へ遷移する。
- 不正なスキーム・ホスト、`code` なし、またはコード形式が不正なURLは無視する。
- 静的共有の取り込みリンク `mahjong-score://import?code=…` は廃止したため無視する。

### 4.14 使い方ガイド

セットアップ画面右上の「? 使い方」ボタンから使い方ガイドを表示できる。

- ガイドはモーダル表示とする。モーダルは小さめの正方形に近い比率とし、右上の×でいつでも閉じられる（Issue #72）。
- モーダル幅の上限はスマートフォンでは360とし、iPad など画面幅600以上の端末では620かつ画面幅の75%までに広げる（Issue #97）。
- スライドは7枚構成とする（ゲームの始め方／スコアの記録／チップの記録／中断・終了／リアルタイム共有／閲覧モード／過去のゲーム）。
- 各スライドにはタイトル（傾けないバッジ表示。Issue #94 で傾きを削除）、アプリ画面の画像、明るい一言の説明（例: 「名前を入れてゲーム開始！」）を表示する（Issue #74 で手順の箇条書きから一言に変更）。ページごとにアクセント色と淡い背景色を切り替える。
- 画像は `generate_assets.py` で App Store 掲載画像と同じ画面モックアップから各ページで説明する部分を 4:3 で切り出した `assets/guide/guide_*.png` を使う（Issue #72。`python3 generate_assets.py --guide-only` で再生成できる）。画像のデザインは、カードを左右交互に少し傾け、角に丸いステッカーを重ねたもの（Issue #75 のデザイン。Issue #80 でいったん傾けない配置にしたが、Issue #100 で戻した）とする。
- 左右のスワイプでページをめくれる。前へ（←）・次へ（→）ボタン、最後のページの「閉じる」ボタンでも操作できる（Issue #72）。
- ページ幅はモーダル外枠の内側にある FlatList の実際の表示幅（`onLayout` で測定）とし、スワイプのたびにページ位置がずれないようにする（Issue #92）。
- ドットインジケーターと「n / 7」で現在位置を表示する。ドットをタップするとそのページへ移動する。

### 4.15 保存データクリア（廃止）

保存データを全削除する「保存データをクリア」機能は Issue #81 で廃止した（Issue #60 でセットアップ画面から過去ゲーム一覧の末尾に移動していたボタンと、全データ削除処理を削除）。不要なゲームは過去ゲーム一覧の選択削除（4.10節）で削除する。

### 4.16 スクロール補助

ゲーム画面では、縦スクロール量が一定値を超えた場合にトップへ戻るボタンを表示する。

- 表示閾値はスクロールオフセット `200` 超過とする。
- ボタンはフェードイン・フェードアウトする。
- タップすると画面最上部へアニメーションスクロールする。

### 4.17 リアルタイム共有

進行中ゲームのスコアを、同じ卓のメンバーが各自の端末でリアルタイムに閲覧できる（Issue #43）。同期基盤には Firebase Firestore（Firebase JS SDK）を使い、匿名認証でアクセスする。編集はホストのみで、参加者は閲覧のみとする。

#### ホスト側

- 進行中ゲーム画面のヘッダー下に「リアルタイム共有を開始」ボタンを表示する。通常のボタンと分かるよう、塗りつぶしの背景色・余白・十分なタップ領域（高さ56pt以上）を持たせる（Issue #53）。
- 開始すると6桁の数字のセッションコードを発行し、Firestore の `sessions/{code}` に現在のゲームを保存する（7.1節）。
- 開始後はコード表示モーダルを開く。モーダルではコード・有効期限を表示し、コードのコピーができる。説明文は「「ゲームを取り込む」にこのコードを入力すると閲覧できます」とする（Issue #60 で簡潔にした）。共有シートでの「送信する」ボタンと「共有を終了」ボタンは Issue #53 で削除した。
- 共有中はボタンが「リアルタイム共有中 コード: 123456」表示に変わり、有効期限も表示する（Issue #60）。タップでモーダルを再表示できる。
- ホストの共有中画面は通常の配色（青）のままとする。黄色基調の背景はゲストの閲覧モードだけに適用する（Issue #58。Issue #53 ではホストも黄色基調にしていた）。
- スコア記録、チップ記録、半荘削除、チップ削除のたびに、セッションのゲームデータを更新する。
- 同期に失敗した場合は共有ボタン内に警告を表示する。次回の記録時に最新状態を再送する。
- セッションコードと有効期限はゲームに紐づけてローカルに保存し、中断・再開後も共有を継続する。再開時に最新状態を一度送信する。
- 同期は自動（入力のたびに送信）で行う。ゲーム終了時にセッションを終了状態にする。それ以外は有効期限（48時間）で終了する。
- 有効期限（作成から48時間）を過ぎたセッションには同期せず、共有中状態を解除する。
- 終了済みゲームの共有（4.11節）も同じセッションの仕組みを使う。
- 匿名ユーザーは端末内に永続化し、アプリ再起動後も同じホストとして書き込める。

#### 参加者側

- セットアップ画面の「ゲームを取り込む」にセッションコードを入力する、またはセッションリンクを開くとライブ閲覧画面に遷移する。有効期限切れのセッションは閲覧できない（後述、Issue #108）。
- コード入力欄は6つの枠に1桁ずつ数字だけを入れる形式とし、数字キーボードを表示する。6桁そろうまで「取り込む」は押せない。セッションリンクを貼り付けた場合はリンク内のコードを取り出す（Issue #53）。
- ライブ閲覧中は背景を黄色基調にする（Issue #53）。ホストが共有を終了した後も閲覧モードの表示（黄色の背景・`閲覧モード` バッジ）のままとし、バナーの見出しを「閲覧中（共有終了）」にして、同期が止まり最後に受信した内容を表示していることを伝える（Issue #72）。
- 接続中（最初のデータを受信するまで）はローディング表示のみとし、「総合スコア」「記録履歴」も表示しない（Issue #58）。
- 閲覧モードのバナーは「閲覧中」「ホストの入力が自動で反映されます（編集不可）」と表示し、セッションコードは表示しない（Issue #58）。
- 終了済みゲームの共有コード（4.11節）でも同じ画面に遷移し、最初から終了状態で表示する。
- ライブ閲覧画面は既存の読み取り専用詳細画面（総合スコア・記録履歴）と同じ表示で、ヘッダーに状態バッジ（`閲覧モード` / `接続中`）を表示する。共有終了後のバッジは灰色の `閲覧モード` とする（Issue #72）。
- ホストの更新は再読み込みなしで即時反映する。
- セッションが存在しない、または接続できない場合はエラーを表示してセットアップ画面に戻る。ただし、そのコードの対局をすでに取り込み済み（履歴に保存済み）の場合はエラーにせず、保存済みの対局を開く（Issue #72）。
- すでに取り込み済みのコードを「ゲームを取り込む」に入力した場合はエラーにせず「取り込み済み」と表示し、「開く」で既存の対局を開く。受信元セッションが有効期限内として記録されていれば閲覧モードで、そうでなければ保存済みの対局（読み取り専用）で開く。取り込み元のコードは `games.source_session_code` に記録して判定する（Issue #72）。
- ホストが共有を終了した（終了済みゲームの共有を含む）場合は、有効期限内であれば「対局を履歴に保存」ボタンを表示する。接続が切れた場合も、有効期限内であれば最後に受信した内容を保存できる。
- 有効期限切れ（Issue #108）: 有効期限（作成から48時間）を過ぎたセッションは、ホストが終了済みでも期限切れとして扱い（期限切れを終了より優先）、閲覧・履歴への保存はできない。
  - 参加時点で期限切れの場合（コード入力・セッションリンク）は、内容を表示せず「有効期限切れ」のエラー（「セッション「123456」の有効期限が切れました。閲覧・保存はできません」）を表示し、「OK」でセットアップ画面に戻る。
  - 閲覧中に有効期限を迎えた場合は、その時点で表示中の内容（総合スコア・記録履歴・プレイヤー名）と「対局を履歴に保存」ボタンを消し、バナーを「有効期限切れ」「セッションの有効期限が切れました 閲覧を終了します」に切り替えて、「有効期限切れ」の知らせ（「セッションの有効期限が切れたため、閲覧を終了します」）を表示する。「OK」で閲覧を終了し、遷移元の画面（セットアップ画面、または過去のゲーム一覧から入った場合は一覧）に戻る。最後に受信した内容を表示し続けない。
  - 期限の判定は Firestore のデータ受信時に加え、閲覧中は有効期限の時刻にタイマーで行う。タイマーの通知より先に「対局を履歴に保存」が押された場合（バックグラウンドからの復帰直後など）も、有効期限を過ぎていれば保存しない。
  - すでに自分の履歴に保存済み（取り込み済み）の対局は影響を受けない。参加時点で期限切れでも、そのコードの対局を取り込み済みであればエラーにせず保存済みの対局を開く。閲覧中に保存した後に期限を迎えた場合は、知らせに「保存済みの対局を開く」を表示する。
  - 期限切れになったセッションの参加記録（`joined_sessions`）は削除する（再入室の一覧には出さない）。
- 保存すると、終了済みかつ取り込み済み（`共有` バッジ付き）のゲームとして保存する。保存は一度のみで、同じコードの対局を取り込み済みの場合は最初から「保存済み」と表示し二重に保存しない（Issue #72）。セッションが進行中に保存した場合は、受信元のセッションコードと有効期限も記録する。

#### 過去のゲーム一覧からの遷移（Issue #53）

- 「過去のゲーム」一覧の先頭に、ホストとしてリアルタイム共有中（有効期限内）の進行中ゲームを `● 共有中（進行中）` バッジ付き・黄色の枠で表示する。選ぶとそのゲーム画面（共有中）に遷移する。選択削除（4.10節）の対象にはできない。
- 受信元セッションが有効期限内の取り込み済みゲームは `● 共有中` バッジを表示し、選ぶと通常の過去ゲーム表示ではなくライブ閲覧画面に遷移する。ライブ閲覧から戻ると一覧に戻る。

#### 閲覧モードへの再入室（Issue #58）

- ゲストとしてセッションのデータを受信するたびに、参加したセッション（コード・有効期限・状態・開始日・プレイヤー名・半荘数）を端末の `joined_sessions` テーブル（5.7節）に保存する。
- 「過去のゲーム」一覧の先頭に、参加したセッションのうち有効期限内で、まだ履歴に保存していないものを `● 閲覧モード`（共有終了後は `閲覧モード（共有終了）`）バッジ付き・黄色の枠で表示する。選ぶとコード入力なしでライブ閲覧画面に入り、戻ると一覧に戻る。
- セットアップ画面の「過去のゲームを見る」ボタンは、終了済みゲームがなくても再入室できるセッションがあれば表示する。
- 長押しすると確認ダイアログを表示し、一覧から削除できる（セッション自体には影響しない。再度見るにはセッションコードの入力が必要）。
- セッションが存在しない・期限切れになった場合、および「対局を履歴に保存」した場合は参加記録を削除する。期限切れの記録は一覧表示時にも削除する。

#### 静的共有の廃止

- 以前の静的共有（対局データを deflate 圧縮 + Base64 化した共有コード、および `mahjong-score://import?code=…` リンク）は Issue #46 で廃止した。発行・取り込みとも行えず、過去に発行された静的コードも読み込めない。
- 共有はセッションコード方式に一本化した。共有データの形式（6章 v2形式JSON）はセッションの `data` として引き続き使用する。
- 既存の対局データ・履歴（SQLite）には影響しない。

## 6. 共有データ形式

### 6.1 用途

共有データはセッションドキュメント `sessions/{code}` の `data` フィールド（7.1節）に JSON 文字列として保存する。リアルタイム共有・終了済みゲームの共有で共通の形式とする。圧縮・Base64 化は行わない（静的共有コードは廃止）。

### 6.2 v2形式

ホストが送信する形式は v2 とする（`database.ts` の `buildShareData`）。

| キー | 型 | 説明 |
| --- | --- | --- |
| `v` | number | データバージョン。`2` |
| `pc` | number | プレイヤー数 |
| `d` | string | ゲーム開始日 |
| `p` | string[] | プレイヤー名配列 |
| `s` | array[] | スコア配列 |
| `c` | array[] | チップ配列。存在する場合のみ |

`s` の要素は次のどちらかとする。

- `[hanchan, playerIndex, point]`
- `[hanchan, playerIndex, point, timestamp, formattedTime]`

`c` の要素は次のどちらかとする。

- `[hanchan, playerIndex, chipPoint]`
- `[hanchan, playerIndex, chipPoint, timestamp, formattedTime]`

### 6.3 v1互換

展開処理（`shareDataToRecords`）とバリデーションは v1 形式にも対応する。v1 はプレイヤー名を各スコア・チップ要素内に保持する形式である。

- スコア: `[hanchan, playerName, point, rank, timestamp, formattedTime]`
- チップ: `[hanchan, playerName, chipPoint, timestamp, formattedTime]`

### 6.4 バリデーション

共有データは最低限次の条件を満たす必要がある。

- オブジェクトである。
- `v` が `1` または `2` である。
- `pc` が数値である。
- `d` が文字列である。
- `p` が文字列配列である。

### 6.5 共有データの展開

ライブ閲覧と履歴への保存は共通の `shareDataToRecords` で共有データを記録行に展開する。v2 は半荘ごとに順位を再計算する。タイムスタンプを持たない旧データは、スコアに取り込み時刻、チップに半荘ごとに異なる時刻を割り当てる。

## 7. リアルタイム共有データ

### 7.1 `sessions/{code}`（Firestore）

| フィールド | 型 | 説明 |
| --- | --- | --- |
| `data` | string | 6.2節 v2形式の共有データの JSON 文字列。Firestore は入れ子配列を保存できないため文字列で持つ |
| `hostUid` | string | 作成したホストの匿名ユーザーID |
| `createdAt` | timestamp | 作成日時 |
| `updatedAt` | timestamp | 最終更新日時 |
| `expiresAt` | timestamp | 有効期限。作成から48時間後 |
| `ended` | boolean | ホストが共有を終了したか。終了済みゲームの共有（4.11節）では作成時から `true` |

### 7.2 セッションコード

- 数字（`0`〜`9`）のみの6桁とする（100万通り、Issue #48）。有効期限（48時間）と一覧取得の禁止（7.3節）により推測耐性を確保する。
- 入力時は空白とハイフンを除去する。
- 英数字コード（Issue #48 以前の形式）は無効なコードとして扱う。
- 発行時に同じコードのドキュメントが存在する場合は別のコードで再試行する（最大5回）。
- セッションリンクは `mahjong-score://live?code=<code>` 形式とする。

### 7.3 アクセス制御（`firestore.rules`）

- 匿名認証済みユーザーのみアクセスできる。
- コードを指定した読み取りは可能、一覧取得は不可とする。
- 作成は `hostUid` が自分であり、コード形式・フィールド許可リスト・`data` のサイズ上限・有効期限（作成時刻から49時間以内）が妥当な場合のみ許可する。`ended` は真偽値であればよく、進行中（`false`）と終了済み（`true`）のどちらのセッションも作成できる。
- 更新はホストのみ、有効期限内のみ、`data`・`updatedAt`・`ended` の変更のみ許可する。

## 8. 日付・時刻仕様

- ゲーム開始日は `YYYY/MM/DD` 形式で保存する。
- 記録表示時刻は `M月D日HH:mm` 形式で保存する。
- 日付生成は端末ローカル時刻に依存する。

## 10. 削除仕様

- ゲーム削除は `chips`、`scores`、`game_players`、`games` の順に明示的に削除する。
- 過去ゲーム一覧の選択削除（4.10節）は、選択したゲームを同じ順序で1つのトランザクションでまとめて削除する（`deleteGames`）。
- 全データクリアは Issue #81 で廃止した（4.15節）。
- 外部キーは `ON DELETE CASCADE` を指定しているが、実装は明示削除も行う。
- 記録なしゲームの終了確定時は、終了済みにせずゲーム自体を削除する。
- 保存上限（お気に入りを含めて合計100件）を超えた分は、保存時に古い通常データ（お気に入り以外）から自動削除する（4.10節）。

`__tests__/liveSession.test.ts` では次の仕様を確認している（Firestore 通信はモック）。

- セッションコードの生成・正規化・形式判定、セッションリンクの生成と解析。
- 取り込み欄の入力がセッションコードかどうかの判別（静的共有コード・リンクは対象外）。
- セッションドキュメントの生成（48時間の有効期限、終了済みとしての生成）と、状態（live / ended / expired）の判定（期限切れを優先）。
- 共有データから記録行への展開（v1・v2、旧データのフォールバック）。
- セッション作成時のコード衝突時の再試行、更新・終了、参加者への変更通知、購読解除、エラー通知。
- 終了済みセッションの発行（`publishFinished`）: 最初から `ended: true`・48時間の有効期限で作成すること、呼ぶたびに新しいコードを発行すること、衝突時のエラー、参加者に終了状態で通知され、48時間後は内容を渡さず期限切れ（`expired`）として通知されること。
- 有効期限切れの参加（Issue #108）: 期限切れのセッション（ちょうど期限の時刻、ホストが終了済みのものを含む）は内容を通知せず `expired` を通知して購読を解除すること、ホストが終了したセッションでも期限内なら内容を通知すること、閲覧中に有効期限を迎えるとその時点で `expired` を通知して購読を終えること（以降のイベントは通知しない）、期限前に購読を解除すると期限のタイマーも止まること。
- 閲覧画面の表示内容（`describeLiveViewer`）: 共有終了は閲覧モードのまま最後の内容を表示し、期限切れは最後の内容を表示せず閲覧を終了することを伝えること。

`__tests__/screens/LiveViewer.test.tsx`（画面操作のテスト）では、閲覧モードの有効期限切れ（Issue #108）について次の仕様を確認している（Firestore はメモリ上のモック）。

- 期限切れのセッション（ホストが終了済みのものを含む）に参加すると、内容も「対局を履歴に保存」も表示せず「有効期限切れ」のエラーを表示し、「OK」で戻ること。履歴にも保存されないこと。
- 「ゲームを取り込む」に期限切れのコードを入力すると、エラーを表示してセットアップ画面に戻ること。
- ホストが終了したセッションは、有効期限内なら閲覧して履歴に保存できること。
- 閲覧中（進行中・共有終了のどちらも）に有効期限を迎えると、表示中の内容と保存ボタンを消して期限切れを知らせ、閲覧を終了すること。期限の通知より先に保存ボタンを押しても、期限を過ぎていれば保存しないこと。
- 取り込み済みの対局は影響を受けないこと: 期限切れ・セッション不存在でも保存済みの対局を開くこと（Issue #72）、閲覧中に保存した後に期限を迎えた場合は保存済みの対局を開けること。

## 13. 非機能・運用上の前提

- データは端末ローカルの SQLite に保存する。
- アカウント機能は持たない。サーバー通信はゲーム共有（Firebase 匿名認証・Firestore）のみで、共有するゲームデータだけを送信する。
- 共有はセッションコード（またはセッションリンク）で行う。進行中ゲームはリアルタイム共有、終了済みゲームは終了状態のセッションとして共有する。いずれも有効期限は作成から48時間。
- 共有セッションはセッションコードを知っている人なら誰でも閲覧できる。
- Firestore のセキュリティルールは `firestore.rules` で管理し、Firebase CLI（`firebase deploy --only firestore:rules`）で反映する。期限切れセッションの自動削除には `expiresAt` を対象とした TTL ポリシーを設定できる。
- 共有データは暗号化しない平文の JSON であり、秘匿用途ではない。
- 画面表示とアラート文言は日本語を前提とする。
