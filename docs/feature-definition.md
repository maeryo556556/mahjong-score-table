# 機能定義書

## 1. 文書情報

- 対象アプリ: 麻雀スコアシートモバイル
- 対象バージョン: `package.json` の `1.1.1`
- 対象プラットフォーム: Expo / React Native による iOS、Android、Web
- 参照元: `README.md`、`app/`、`screens/`、`components/`、`database.ts`、`utils.ts`、`__tests__/`

## 2. アプリ概要

麻雀スコアシートモバイルは、3人麻雀または4人麻雀の半荘ごとのポイント、チップ移動、順位、総合結果をローカル端末上で記録・閲覧・共有するモバイルアプリである。

主な利用シーンは次のとおり。

- プレイヤー名と人数を指定して新規ゲームを開始する。
- 半荘ごとのスコアを入力し、順位を自動判定して保存する。
- 半荘に紐づくチップ移動を別途記録する。
- 現在の総合スコア、順位分布、記録履歴を確認する。
- ゲームを中断、再開、終了する。
- 終了済みゲームを過去履歴として閲覧、削除、共有する。
- 共有リンクまたは共有コードからゲームを取り込む。

## 3. 画面構成と遷移

### 3.1 ルート処理

`app/_layout.tsx` はアプリ起動時に SQLite データベースを初期化し、ディープリンクを監視する。`mahjong-score://import?code=<code>` 形式のリンクを受け取った場合は共有コードを取り込み、取り込んだゲームの閲覧画面へ遷移する。

進行中ゲームが存在する状態でディープリンクを受け取った場合は確認ダイアログを表示し、ユーザーが承認したときに進行中ゲームを終了扱いにしてからインポートする。

### 3.2 メイン画面状態

`app/index.tsx` は次の画面状態を管理する。

| 状態 | 表示画面 | 用途 |
| --- | --- | --- |
| `setup` | `SetupScreen` | 初期設定、再開、履歴、インポート |
| `game` | `GameScreen` | 進行中ゲームの入力・集計 |
| `pastGames` | `PastGamesScreen` | 終了済みゲーム一覧 |
| `viewPastGame` | `GameScreen` | 過去ゲームまたは取り込みゲームの読み取り専用閲覧 |

起動時に未終了ゲームがある場合は、自動的に `game` 状態で再開する。URLパラメータ `viewGameId` が渡された場合は、対象ゲームを読み取り専用で表示する。

### 3.3 基本遷移

- `SetupScreen` から新規ゲーム開始または中断ゲーム再開で `GameScreen` に遷移する。
- `GameScreen` で中断すると `SetupScreen` に戻る。
- `GameScreen` でゲーム終了すると `SetupScreen` に戻る。
- `SetupScreen` から過去ゲーム一覧へ進み、一覧からゲームを選択すると読み取り専用の `GameScreen` に遷移する。
- 共有コードの手動取り込みまたはディープリンク取り込みに成功すると、取り込んだゲームを読み取り専用で表示する。

## 4. 機能定義

### 4.1 ゲーム設定

ユーザーはセットアップ画面で麻雀タイプとプレイヤー名を設定できる。

- 麻雀タイプは3人麻雀または4人麻雀から選択する。
- プレイヤー名は選択した人数分だけ入力する。
- プレイヤー名は必須で、最大4文字までとする。
- 入力エラーがある場合、ゲームは開始せずアラートを表示する。
- 中断中ゲームが存在する状態で新規ゲームを開始する場合、確認後に中断中ゲームを整理する。
- 半荘記録もチップ記録もない中断ゲームは削除する。
- 記録がある中断ゲームは終了済みとして保存する。

### 4.2 中断中ゲームの再開

未終了のゲームはセットアップ画面に一覧表示される。

- 表示内容は開始日、麻雀タイプ、プレイヤー名、半荘数とする。
- 一覧項目をタップすると該当ゲームを再開する。
- アプリ起動時に未終了ゲームがある場合は、最新の未終了ゲームを自動的に開く。

### 4.3 ポイント入力とスコア記録

進行中ゲームでは、プレイヤーごとにドラムロール入力 UI で半荘ポイントを入力する。

- 入力単位は `+10`、`+1`、`-10`、`-1` とする。
- 入力範囲は `-200` から `+200` までとする。
- 初期値は全員 `0` とする。
- 正の値は緑、負の値は赤、ゼロは通常色で表示する。
- 入力中の合計値を表示し、合計がゼロでない場合はエラー色で示す。
- リセット操作で全プレイヤーの入力値を `0` に戻せる。

スコア記録時の制約は次のとおり。

- 全員 `0` の場合は記録できない。
- 合計が `0` でない場合は記録できない。
- 記録時にポイント降順で順位を自動判定する。
- 同点の場合は同順位とし、次順位は競技順位方式で採番する。例: 1位タイが2人いる場合、次は3位。
- 記録成功時は現在の半荘番号で保存し、次の半荘番号へ進め、入力値をリセットする。

### 4.4 チップ移動記録

進行中ゲームでは、スコアとは別にチップ移動を記録できる。

- 入力 UI、入力範囲、色分け、リセット操作はポイント入力と同等とする。
- 全員 `0` の場合は記録できない。
- 合計が `0` でない場合は記録できない。
- 記録先の半荘番号は現在のスコア入力対象の一つ前、すなわち直近で記録済みの半荘とする。
- 記録成功時はチップ入力値をリセットする。

### 4.5 総合スコア表示

`SummaryCards` はゲーム中および読み取り専用閲覧時に総合結果を表示する。

- プレイヤーごとに、スコア合計とチップ合計を足した総合スコアを表示する。
- 総合スコアは正の値を緑、負の値を赤、ゼロを通常色で表示する。
- 順位ごとの回数をバッジで表示する。
- チップ合計がゼロでない場合はチップ合計を補足表示する。

### 4.6 記録履歴表示

`HistoryTable` はスコア履歴とチップ履歴を統合して新しい順に表示する。

- スコア履歴は半荘ごとにグループ化して表示する。
- チップ履歴は同一タイムスタンプごとにグループ化して表示する。
- スコア行には半荘番号、記録日時、プレイヤー別ポイント、順位バッジを表示する。
- チップ行にはチップ記録日時とプレイヤー別チップ値を表示する。
- 編集可能状態では、長押し操作で削除確認を表示する。
- 読み取り専用状態では、長押し削除を無効にする。

### 4.7 記録削除

進行中ゲームでは履歴から記録を削除できる。

- 半荘スコア行を長押しすると、その半荘のスコア記録と同じ半荘番号のチップ記録を削除する。
- 半荘削除後、残った半荘は記録時刻順に `1` から採番し直す。
- チップ行を長押しすると、そのチップ移動グループのみを削除する。
- 削除前には確認ダイアログを表示する。

### 4.8 ゲーム中断

進行中ゲームでは中断操作ができる。

- 中断ボタン押下時に確認ダイアログを表示する。
- 中断したゲームは `finished = 0` のまま保持する。
- 中断後はセットアップ画面に戻り、中断中ゲーム一覧から再開できる。

### 4.9 ゲーム終了

進行中ゲームでは終了操作ができる。

- ゲーム終了ボタン押下時に最終結果モーダルを表示する。
- モーダルには総合スコア順のランキング、上位メダル、順位回数を表示する。
- 確定時、記録が一件もないゲームは削除する。
- 確定時、記録があるゲームは `finished = 1` に更新して終了済みとして保存する。
- 終了後はセットアップ画面に戻る。

### 4.10 過去ゲーム一覧

終了済みゲームは過去ゲーム一覧で閲覧できる。

- 一覧には開始日、麻雀タイプ、プレイヤー名、半荘数を表示する。
- 共有コードから取り込まれたゲームには `共有` バッジを表示する。
- タップすると読み取り専用の詳細画面を開く。
- 長押しすると削除確認を表示し、承認後にゲーム一式を削除する。
- 終了済みゲームが存在しない場合は空状態メッセージを表示する。

### 4.11 ゲーム共有

読み取り専用のゲーム詳細画面ではゲーム共有ができる。

- 共有ボタン押下時に対象ゲームを共有コードへエクスポートする。
- 共有リンクは `mahjong-score://import?code=<encoded>` 形式とする。
- 共有モーダルでは共有リンクを表示し、OS標準共有シートで送信できる。
- 共有リンクはクリップボードにコピーできる。
- 共有コード生成に失敗した場合はエラーアラートを表示する。

### 4.12 ゲーム取り込み

セットアップ画面では共有リンクまたは共有コードからゲームを取り込める。

- 入力が空の場合は取り込めない。
- 入力がディープリンク形式の場合は `code` パラメータを抽出する。
- 入力がディープリンク形式でない場合は入力値全体を共有コードとして扱う。
- 取り込み成功時はゲームを終了済みかつ取り込み済みとして保存する。
- 取り込み成功後、ユーザーはそのまま閲覧画面へ進める。
- 取り込み失敗時はエラーアラートを表示する。

### 4.13 ディープリンク取り込み

アプリは `mahjong-score://import?code=<encoded>` のディープリンクを処理する。

- コールドスタート時の初期URLを処理する。
- バックグラウンド復帰時のURLイベントを処理する。
- 不正なスキーム、ホスト、または `code` なしのURLは無視する。
- インポートに成功した場合は取り込み完了を通知し、取り込んだゲームの閲覧画面へ遷移する。
- インポートに失敗した場合は取り込みエラーを通知する。

### 4.14 使い方ガイド

セットアップ画面右上のヘルプボタンから使い方ガイドを表示できる。

- ガイドはモーダル表示とする。
- スライドは5枚構成とする。
- 各スライドにはタイトル、手順、アプリ画面モックアップを表示する。
- 前へ、次へ、閉じるボタンで操作する。
- ドットインジケーターで現在位置を表示する。

### 4.15 保存データクリア

セットアップ画面から保存データを全削除できる。

- 実行前に確認ダイアログを表示する。
- 承認後、ゲーム、プレイヤー、スコア、チップの全データを削除する。
- 削除後は過去ゲーム表示状態と中断ゲーム表示状態を更新する。

### 4.16 スクロール補助

ゲーム画面では、縦スクロール量が一定値を超えた場合にトップへ戻るボタンを表示する。

- 表示閾値はスクロールオフセット `200` 超過とする。
- ボタンはフェードイン・フェードアウトする。
- タップすると画面最上部へアニメーションスクロールする。

## 5. データ定義

### 5.1 SQLite データベース

データベース名は `mahjong.db` とする。

### 5.2 `games`

| カラム | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | INTEGER | yes | 主キー、自動採番 |
| `player_count` | INTEGER | yes | プレイヤー数。3または4 |
| `start_date` | TEXT | yes | ゲーム開始日。`YYYY/MM/DD` |
| `created_at` | INTEGER | yes | 作成日時。Unix time |
| `finished` | INTEGER | yes | 0: 未終了、1: 終了 |
| `imported` | INTEGER | yes | 0: 通常作成、1: 共有コードから取り込み |

`finished` と `imported` は既存DB向けに `ALTER TABLE` によるマイグレーションを行う。

### 5.3 `game_players`

| カラム | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | INTEGER | yes | 主キー、自動採番 |
| `game_id` | INTEGER | yes | `games.id` への参照 |
| `player_name` | TEXT | yes | プレイヤー名 |
| `sort_order` | INTEGER | yes | 表示順 |

### 5.4 `scores`

| カラム | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | INTEGER | yes | 主キー、自動採番 |
| `game_id` | INTEGER | yes | `games.id` への参照 |
| `hanchan` | INTEGER | yes | 半荘番号 |
| `player_name` | TEXT | yes | プレイヤー名 |
| `point` | INTEGER | yes | 半荘ポイント |
| `rank` | INTEGER | yes | 自動判定された順位 |
| `timestamp` | INTEGER | yes | 記録日時 |
| `formatted_time` | TEXT | yes | 表示用日時。`M月D日HH:mm` |

### 5.5 `chips`

| カラム | 型 | 必須 | 説明 |
| --- | --- | --- | --- |
| `id` | INTEGER | yes | 主キー、自動採番 |
| `game_id` | INTEGER | yes | `games.id` への参照 |
| `hanchan` | INTEGER | yes | 紐づく半荘番号 |
| `player_name` | TEXT | yes | プレイヤー名 |
| `chip_point` | INTEGER | yes | チップポイント |
| `timestamp` | INTEGER | yes | 記録日時 |
| `formatted_time` | TEXT | yes | 表示用日時。`M月D日HH:mm` |

### 5.6 インデックス

- `idx_scores_game` on `scores(game_id)`
- `idx_scores_hanchan` on `scores(game_id, hanchan)`
- `idx_chips_game` on `chips(game_id)`
- `idx_game_players_game` on `game_players(game_id)`

## 6. 共有データ形式

### 6.1 エンコード方式

共有コードは次の手順で生成する。

1. 共有データオブジェクトを JSON 文字列化する。
2. `TextEncoder` で UTF-8 バイト列に変換する。
3. `pako` の `deflate` で圧縮する。
4. Base64 文字列に変換する。

デコード時はBase64をバイト列へ戻し、`inflate` を試行する。失敗した場合は旧形式の非圧縮Base64としてデコードする。

### 6.2 v2形式

現在のエクスポート形式は v2 とする。

| キー | 型 | 説明 |
| --- | --- | --- |
| `v` | number | データバージョン。`2` |
| `pc` | number | プレイヤー数 |
| `d` | string | ゲーム開始日 |
| `p` | string[] | プレイヤー名配列 |
| `s` | array[] | スコア配列 |
| `c` | array[] | チップ配列。存在する場合のみ |

`s` の要素は次のどちらかとする。

- `[hanchan, playerIndex, point]`
- `[hanchan, playerIndex, point, timestamp, formattedTime]`

`c` の要素は次のどちらかとする。

- `[hanchan, playerIndex, chipPoint]`
- `[hanchan, playerIndex, chipPoint, timestamp, formattedTime]`

### 6.3 v1互換

取り込み処理は v1 形式にも対応する。v1 はプレイヤー名を各スコア・チップ要素内に保持する形式である。

- スコア: `[hanchan, playerName, point, rank, timestamp, formattedTime]`
- チップ: `[hanchan, playerName, chipPoint, timestamp, formattedTime]`

### 6.4 バリデーション

共有データは最低限次の条件を満たす必要がある。

- オブジェクトである。
- `v` が `1` または `2` である。
- `pc` が数値である。
- `d` が文字列である。
- `p` が文字列配列である。

## 7. 日付・時刻仕様

- ゲーム開始日は `YYYY/MM/DD` 形式で保存する。
- 記録表示時刻は `M月D日HH:mm` 形式で保存する。
- 日付生成は端末ローカル時刻に依存する。

## 8. バリデーション一覧

| 対象 | 条件 | エラー時の動作 |
| --- | --- | --- |
| プレイヤー名 | 空でない | 入力エラーアラート |
| プレイヤー名 | 4文字以内 | 入力エラーアラート |
| スコア入力 | 全員0ではない | 入力エラーアラート |
| スコア入力 | 合計が0 | 入力エラーアラート |
| チップ入力 | 全員0ではない | 入力エラーアラート |
| チップ入力 | 合計が0 | 入力エラーアラート |
| 共有取り込み | 入力が空でない | 入力エラーアラート |
| 共有取り込み | デコード可能かつ形式が妥当 | エラーアラート |

## 9. 削除仕様

- ゲーム削除は `chips`、`scores`、`game_players`、`games` の順に明示的に削除する。
- 全データクリアも同じ順序で全件削除する。
- 外部キーは `ON DELETE CASCADE` を指定しているが、実装は明示削除も行う。
- 記録なしゲームの終了確定時は、終了済みにせずゲーム自体を削除する。

## 10. テストで確認されている仕様

`__tests__/utils.test.ts` では次の仕様を確認している。

- 順位計算、同順位、未入力プレイヤーの0点扱い。
- 全員ゼロ判定、合計計算、値のクランプ。
- 共有コードのエンコード・デコード。
- 日本語プレイヤー名を含む共有データのラウンドトリップ。
- 共有データの形式検証。
- 共有URL生成とURL解析。
- 日付・時刻フォーマット。

`__tests__/deeplink.test.ts` では次の仕様を確認している。

- ディープリンクURLの解析。
- アクティブゲームなしでの即時インポート。
- アクティブゲームありでの確認分岐。
- 確認後にアクティブゲームを終了してからインポートする処理順。
- インポートエラー時のアラート。
- 無関係なURLを無視すること。

## 12. 非機能・運用上の前提

- データは端末ローカルの SQLite に保存する。
- サーバー同期やアカウント機能は持たない。
- 共有はリンクまたはコードを介したエクスポート・インポートで行う。
- 共有データは暗号化ではなく圧縮Base64であり、秘匿用途ではない。
- 画面表示とアラート文言は日本語を前提とする。
